# Tasks: Aurora Main Screen

**Input**: Design documents from `specs/001-aurora-main-screen/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md),
[data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md)

**Tests**: Included. The constitution (Principle IV) requires test-first development for the core
(parsing, R value, probability, caching): write each test task first and see it fail before the
matching implementation task. UI flows are covered by UI tests.

**Organization**: Tasks are grouped by user story so each story can be implemented and tested on
its own.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: Which user story the task belongs to (US1, US2, US3)

## Path Conventions

- Core package: `Packages/AuroraCore/Sources/AuroraCore/`, tests in
  `Packages/AuroraCore/Tests/AuroraCoreTests/`
- iOS app: `Revontulet/`, UI tests in `RevontuletUITests/`
- Development tools: `tools/`
- Rules for all core code: no imports of SwiftUI, UIKit, CoreLocation, Combine, os/OSLog or
  `XMLParser`; use `#if canImport(FoundationNetworking)` for URLSession; all public types
  `Sendable` (research R10).
- All UI work (views, layout, visual polish) MUST use the `ios-ui-craft` skill (Principle VI).

## Phase 3: User Story 1 - See my chance of seeing the aurora (Priority: P1) 🎯 MVP

### Phase Dependencies

  user stories.

### Within Each User Story

- Test tasks first; confirm they fail; then the implementation task named in "makes Txxx pass".
- Core (package) before app; model before view; strings after the views that use them.
- Commit after each task or logical group; every commit must build and pass tests (constitution).

- Setup: T003, T004, T005, T006 in parallel after T001/T002.
- Foundational: tests T008–T011 in parallel; then T012–T016 in parallel; T017 last.
- US1: tests T018–T024 in parallel; then T025–T030 and T032 in parallel; then T031, T033–T038.
